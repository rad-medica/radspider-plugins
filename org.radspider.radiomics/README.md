# Radiomics (pyradiomics)

Plugin id: `org.radspider.radiomics`

TL;DR: the 3D Slicer extension **SlicerRadiomics** is a front end to **pyradiomics**. This plugin is the same front
end for radspider: pyradiomics features of each segment of the series, in one table (feature rows × segment columns)
to save as CSV. radspider also has a native IBSI feature tool; this plugin is the pyradiomics-compatible one, for
results that must match a pyradiomics / Slicer pipeline (same feature names, same diagnostics rows).

| Entry | Does | SlicerRadiomics equivalent |
|---|---|---|
| tool *radiomics* | Interactive window. First run and every control change only redraw the controls; **Extract** computes the enabled feature classes on the chosen segment(s), with progress per segment | *Apply* with "Manual Customization" |

| Control | Default | SlicerRadiomics |
|---|---|---|
| *Segment* (choice) | All segments | Input regions (each segment = one column) |
| *First order*, *Shape (3D)*, *GLCM*, *GLRLM*, *GLSZM*, *GLDM*, *NGTDM* (checkboxes), *All classes* / *No classes* (buttons) | first order only | Feature class boxes, "Calculate all / no features" |
| *Bin width* (number, 0.01 to 10000) | 25 | Bin Width (`binWidth`) |
| *Resampled voxel size* (number, mm, 0 = none) | 0 | Resampled voxel size (`resampledPixelSpacing`) |
| *Symmetrical GLCM* (checkbox) | on | Enforce Symmetrical GLCM (`symmetricalGLCM`) |
| *LoG kernel size 1 / 2 / 3* (numbers, mm, 0 = off) | 0 | LoG kernel sizes (image type `LoG`, `sigma`) |
| *Wavelet features* (checkbox) | off | Wavelet-based features (image type `Wavelet`) |
| *Extract* (button) | | Apply |

| Item | |
|---|---|
| Library | [pyradiomics](https://github.com/AIM-Harvard/pyradiomics), installed from GitHub at commit `67d1f268` (tag `v3.1.1a3`), because nothing on PyPI installs on Python ≥ 3.10: 3.1.0 has wheels for CPython 3.7 to 3.9 only and its sdist fails (`ModuleNotFoundError: No module named 'numpy'` in `setup.py`; seen here with pip 26.2.2 on Python 3.13.18). **The install needs git and a C compiler** (pip clones and compiles two C extensions; 17 s here). The package reports itself as `3.1.0a2.post11+g67d1f26` (`radiomics.__version__`; pip lists it as 3.0.1a1): version numbering of an untagged-release build, not a different code base |
| Pipeline | `volume.numpy()` (slices, rows, columns) → SimpleITK image with the volume's `spacing`, `origin` and direction columns `row`, `col`, `normal` (DICOM patient axes = ITK's LPS); each segment's `mask()` → a mask image on the same grid; `RadiomicsFeatureExtractor.execute` per segment with `binWidth`, `symmetricalGLCM`, `resampledPixelSpacing`, `correctMask=True` (as SlicerRadiomicsCLI), `label=1`, image types `Original` + optional `LoG` / `Wavelet`. Everything else is pyradiomics' default (shown in the `diagnostics_Configuration_Settings` row) |
| Table | First column = pyradiomics key (`diagnostics_…` rows first, then `original_firstorder_Mean`, `log-sigma-2-0-mm-3D_…`, `wavelet-HHL_…`), one column per segment. 107 features with all seven classes on the original image. *Save as CSV…* in the window writes it |
| API 6 (1.1.0) | `api = 6`. Icons (Phosphor): plugin `chart-scatter`, *radiomics* `list-numbers`. Spanish catalog `lang/es.toml` (24 texts; `lang/template.toml` made with `python -m radspider_plugin template`, SDK on `PYTHONPATH`; regenerate it after changing texts). Error messages (`raise`) are not translated: the protocol has no marked error text |
| Translated | Every control label and help, the *Feature* header, progress and messages. The feature names (`original_firstorder_Mean`…), the class acronyms (GLCM, GLRLM, GLSZM, GLDM, NGTDM) and the segment names are identifiers or study data and stay as they are |
| Differences from SlicerRadiomics | (1) Resampling is one isotropic size, not three numbers. (2) At most three LoG kernel sizes (a window has number fields, no text field). (3) No parameter-file mode, no `shape2D`, no verbose switch (pyradiomics warnings go to the plugin log). (4) Voxels without data (NaN) leave the masks and are filled with the lowest value of the series before filtering. (5) The axis-length shape features, which this pyradiomics build returns as complex numbers with zero imaginary part, are written as plain numbers. (6) A segment pyradiomics refuses (empty, one voxel, too small after resampling) gets an `extraction_Error` row and empty cells; the other segments are still computed |
| Limits | The table belongs to the Extract run: changing a control afterwards clears it until Extract is pressed again (each run is a new process, nothing is cached). Bin width is in the unit of the series: 25 suits HU, not SUV or normalised MR. Segments sharing a name are numbered (`Liver (2)`). The segment choice lists the first 255 segments. On a gantry-tilted or unevenly spaced stack the geometry is the SDK's approximation (mean slice step along `normal`) |
| Speed | In the check below (110 × 90 × 44 voxels): 7 classes × 3 segments 0.6 s; first order + GLCM with 2 LoG sizes, wavelet and 2 mm resampling on a 5.7 k-voxel sphere 4.8 s. Wavelet computes every enabled class on 8 filtered copies of the segment's bounding box, LoG on one per kernel size: expect minutes on organ-sized segments of a thin-slice CT (not measured) |
| Licence | pyradiomics: BSD 3-Clause, "Copyright 2017 Harvard Medical School"; SlicerRadiomics: BSD 3-Clause, "Copyright 2018 Harvard Medical School" (both `LICENSE.txt` read from shallow clones of the repositories). No code of either is copied here: pyradiomics is a dependency, SlicerRadiomics only the model for the options. Licences of SimpleITK, PyWavelets and numpy were not read for this page |
| Verified | **Not run in radspider, not on real data.** Run outside the viewer on Linux x86-64, Python 3.13.18, in a venv built from this `requirements.txt` (pyradiomics `3.1.0a2.post11+g67d1f26`, numpy 2.5.4, SimpleITK 2.5.7, PyWavelets 1.10.0), by feeding the SDK's own request handler (`radspider_plugin._handle`) a synthetic request: noisy ellipsoid in HU (60 ± 20 in −1000), 110 × 90 × 44 voxels of 0.9 × 1.1 × 2.5 mm on an oblique grid, three segments in two label layers (ellipsoid, an overlapping sphere, an empty one). Checked: no segments → "No segments: segment a structure first"; first run and a moved control return 18 controls and no table; Extract with all classes: ellipsoid VoxelVolume 95549.9 mm³ = voxel count × voxel volume, MeshVolume 95432.8 mm³, analytic 95504.4 mm³ (+0.05 % / −0.07 %); sphere −0.44 % / −0.90 %; first-order Mean, Minimum, Maximum, Median, Variance, Energy equal to numpy (Mean 59.981229); Major / Minor / Least axis 68.00 / 53.66 / 35.79 mm vs analytic 67.98 / 53.67 / 35.78; centre of mass in patient mm equal to `volume.to_patient` of the mask centroid (axis order, origin and direction); the empty segment gives an `extraction_Error` cell; LoG (2 and 4 mm) + wavelet + 2 mm resampling on a left-handed stack: 11 image types, 462 features; NaN slab: mask voxel count and Mean equal to numpy over the voxels with data. Not checked: values against a Slicer run on the same data, texture features against a reference, real DICOM geometry, the CSV export, Windows / macOS installs |
