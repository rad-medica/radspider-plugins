# Automatic segmentation

Plugin id: `org.radspider.auto-segmentation` · folder: [`../../org.radspider.auto-segmentation`](../../org.radspider.auto-segmentation)

TL;DR: open MPR on a CT, *Segment → Plugins → Automatic segmentation*, pick the *Model*, get its segments. Three model
families in one plugin: TotalSegmentator (117 structures, 3 mm, ONNX Runtime), MONAI whole body (104 structures, 3 or
1.5 mm) and CADS (167 structures in nine groups, 1.5 mm, GPU-class). *Advanced → Plugins → Segmentation models* opens a
window that lists, downloads and deletes their weights. Replaces `org.radspider.totalsegmentator`,
`org.radspider.monai-wholebody` and `org.radspider.cads` (1.1.0 each), whose pipelines it keeps unchanged.

Validator, ruff, marketplace index. ## TotalSegmentator

| Item | |
|---|---|
| Model | TotalSegmentator v2 task 297 (`total`, 3 mm, nnU-Net `PlainConvUNet`), code and weights Apache-2.0 per the project. Other TotalSegmentator tasks (1.5 mm parts, MR, commercial ones) are **not** included |
| First run | Downloads `Dataset297_…total_3mm_1559subj.zip` (135 MB) from the GitHub release `v2.0.0-weights`, **checks its SHA-256 against the value pinned in `autoseg_totalseg.py`** (a mismatch deletes the file and stops), loads the checkpoint (a pickle: `weights_only=False`, only after that check) and exports `total_3mm_v2.0.0.onnx` (65 MB) to `~/.cache/radspider/totalsegmentator` (`RADSPIDER_TOTALSEG_DIR`). Later runs never import PyTorch. `RADSPIDER_TOTALSEG_ONNX=<file>` skips all of it |
| Pipeline | As nnU-Net v2 for this trainer (no mirroring): clip to [-1004, 1588], z-score (−50.39 / 503.39), resample to 3 mm, 112×112×128 window, step 0.5, Gaussian weights, argmax of summed logits, banded along z so memory stays bounded. Differences: linear resampling in (nnU-Net: spline order 3) and labels go back to the series grid by nearest neighbour (nnU-Net resamples the logits). *Window step* trades speed for overlap (0 = 0.5) |
| Limits | CT in HU only. Assumes slices run inferior → superior. 3 mm resolution: small structures (adrenals, small vessels) are coarse |
| Speed | CPU, 122×101×112 voxels: 5.6 s once converted (28.7 s the first time, which includes download and conversion) |
| Verified (as `org.radspider.totalsegmentator` 1.1.0) | Real CT (TotalSegmentator `example_ct_sm.nii.gz`, 30 slices, shorter than the window so the padding path runs) against the project's own `example_seg.nii.gz`: Dice 0.93-0.98 on spleen, kidneys, gallbladder, liver, stomach, lungs, colon, vertebrae; 0.79 pancreas, 0.89 aorta; mean 0.895 over 41 labels. Full `example_ct.nii.gz`: liver Dice 0.97 against the independent MONAI model, organ centroids where expected. SHA-256 mismatch tested (file removed). Not run on a full-body clinical CT, not run through the viewer GUI |

## MONAI whole body

Names: `autoseg_monai.py` `NAMES`, same order as the bundle's `metadata.json`.

| Item | |
|---|---|
| Model | MONAI model zoo bundle [`MONAI/wholeBody_ct_segmentation`](https://huggingface.co/MONAI/wholeBody_ct_segmentation) v0.2.7 (SegResNet, Apache-2.0). Weights downloaded on first run (71 MB per resolution, `huggingface_hub` into `~/.cache/radspider/monai`, `RADSPIDER_MONAI_DIR` moves it); `RADSPIDER_MONAI_WHOLEBODY_WEIGHTS=<file>` for offline. Loaded with `weights_only=True` (plain state dict) |
| Pipeline | `configs/inference.json` rebuilt by hand: RAS, resample 1.5 mm or 3 mm (two entries of *Model*), `NormalizeIntensity(nonzero)`, `ScaleIntensity(-1, 1)`, 96³ Gaussian window, softmax + argmax, nearest back to the series grid. The window keeps one 96-slice band of logits (MONAI's inferer keeps 105 channels of the whole volume: ~20 GB on a body CT at 1.5 mm) |
| Limits | CT in HU only (other units are refused). 1.5 mm needs a few GB of RAM per 100 slices of a body CT (band of fp32, fp16 above 3 GB). Training data: TotalSegmentator dataset (CC BY 4.0, `docs/data_license.txt` of the bundle): keep its notices if shipped |
| Speed | CPU, 3 mm, 122×101×112 voxels: 19 s; 1.5 mm: 79 s. A full body CT takes minutes on CPU; CUDA is used when the plugin's torch has it |
| Verified (as `org.radspider.monai-wholebody` 1.1.0) | Real CT (TotalSegmentator test file `example_ct.nii.gz`, 3 mm, 122×101×112): 3 mm and 1.5 mm runs agree (liver 39-44k voxels, centroids within 3 mm); sides, vertebra order L5→T12 and organ positions anatomically right. **No Dice**: the only reference mask available belongs to a 30-slice crop on which the model is poor. Not run through the viewer GUI |

## CADS

The equivalent of the 3D Slicer extension CADSWholeBodyCTSeg. A GPU-class model: on CPU count 20 s per window (minutes
per group) and 9 GB of RAM. Default weights are CC BY-SA 4.0; the other choice is **non-commercial**.

| Item | |
|---|---|
| Model | CADS-model, [`murong-xu/CADS`](https://github.com/murong-xu/CADS) (code v1.0.3, read at commit `120d678`), paper doi:10.1038/s41467-026-78732-1. Nine nnU-Net v2 networks (`nnUNetTrainerNoMirroring`, `nnUNetResEncUNetLPlans`, `3d_fullres`, `fold_all`, 1.5 mm isotropic, about 102 M parameters each), one per task 551-559. The Slicer extension [`murong-xu/SlicerCADSWholeBodyCTSeg`](https://github.com/murong-xu/SlicerCADSWholeBodyCTSeg) (read at `d06eaf8`) installs that package (pinned to its commit `457638b`) and runs `CADSSlicer`; it has no model code of its own |
| Groups | Nine options of *Model*, with the Slicer extension's titles: 551 core organs (17 structures), 552 spine (24), 553 heart & vessels (18), 554 trunk muscles (21: also the limb-girdle bones), 555 ribs (24), 556 RT risk organs (15), 557 brain tissues (9), 558 head-neck organs (29), 559 body regions (10). No "All" option: the groups overlap (heart of 556 over the chambers of 553, muscle and bone of 559 over everything), so they cannot share one label map; run them one after the other. Segment names: `resources/info/labelmap.md` of the model repository, same order as the `dataset.json` in each weight zip (label count checked at conversion) |
| Weights | GitHub releases of `murong-xu/CADS`: `cads-model-open_v1.0.0/Dataset55x_….zip` (default) or `cads-model-research_v1.0.0/…` (*CADS weights* = research), 761-764 MB per task, 6.9 GB for all nine. The third upstream variant, `cads-model_v1.0.0` ("reference", the one the Slicer extension downloads), is **not offered**: see Licence |
| First run | Per task and variant: downloads the zip, **checks its SHA-256 against the value pinned in `autoseg_cads.py`** (a mismatch deletes the file and stops), unpickles `fold_all/checkpoint_final.pth` (`weights_only=False`: nnU-Net checkpoints hold numpy objects; only after that check) and writes the network weights with the numbers of `plans.json` (window, clip, mean, std, architecture) as a plain file `~/.cache/radspider/cads/<variant>/task55x.pt` (410 MB; `RADSPIDER_CADS_DIR` moves the cache). The zip is then deleted. Later runs read that file with `weights_only=True`. The network class is built by the plugin; plans that name anything but `ResidualEncoderUNet` / `Conv3d` / `InstanceNorm3d` / `LeakyReLU` / `CTNormalization` are refused. Offline: `RADSPIDER_CADS_ZIPS=<folder>` with the upstream zips in `<folder>/open/` or `<folder>/research/` (same hash check) |
| Pins | All 18 hashes (2 variants × 9 tasks) were computed here on the files downloaded from the releases on 2026-11-13. Upstream publishes no checksums, so they say "the file as it was that day", not "the file the authors meant". There is no override: an upstream re-upload needs a new plugin version |
| Pipeline | As `cads/utils/inference.py` `predict`: (1) CADS preprocessing: reorient to RAS (closest axes of the series' `row` / `col` / `normal`; tilt ignored, as upstream), cubic `scipy.ndimage.zoom` to 1.5 mm, truncate to integers; (2) nnU-Net v2 as `nnUNetPredictor(tile_step_size=0.5, use_gaussian=True, use_mirroring=False)`: crop to the non-zero box, clip and z-score with each task's own numbers (e.g. 551 open: [-1022, 330], −476.32 / 456.19), centred zero padding, window 192³ (557: 128×192×192 open, 160×192×192 research; 558: 256×160×160), Gaussian weights, argmax of summed logits, banded along z; mixed precision on CUDA only; (3) CADS post-processing (*CADS post-processing* on): the connected-component rules of `labels_info` for 551, 553, 554, 556, 559 (26-connected, smallest volume, one component for mammary glands, sternum, abdominopelvic cavity and pericardium, hole filling for mammary glands), and for 557 / 558 the head box, below; (4) nearest neighbour back to the series grid, as upstream |
| Head tasks | Upstream keeps of 557 / 558 only a box around the centroid of the brain found by **task 553** (±150 mm in plane, ±200 mm / ±300 mm along the body), returns nothing when that brain is under 2000 voxels, and for 558 falls back to **task 552** (everything above the lowest of labels 14-24) before giving up. The plugin does the same, helper tasks first, so a scan without a head costs one model instead of two. With post-processing on, 557 therefore downloads and runs two models, 558 two or three. Off: the head model alone, everywhere (expect false positives outside the head) |
| Why not `nnunetv2` | Upstream depends on `nnunetv2==2.5.2`, `TPTBox==0.3.0`, `acvl_utils`, SimpleITK, nibabel and writes NIfTI files between steps. The plugin needs four packages (numpy, scipy, torch, `dynamic-network-architectures` for the network class) and re-implements the window, as `totalsegmentator` does. Price: every equivalence below is by reading the code, not by running upstream (see Verified) |
| Why PyTorch at run time, not ONNX | Measured once on task 551, one 192³ window, 4 CPU cores, while downloads were running on the same machine: PyTorch 43 s and 7.4 GB peak, ONNX Runtime 33-42 s and 11.5 GB peak (exported file 409 MB, argmax equal to PyTorch on 99.9994 % of voxels of a random input). Idle, PyTorch takes about 21 s per window; ONNX Runtime was not measured idle. Little or no gain on CPU, 4 GB more memory, and the default `onnxruntime` wheel has no CUDA, which this model needs to be practical. The plain state dict keeps later runs free of pickles all the same |
| Differences from upstream | Resampling in float32 (upstream float64; equal on the synthetic test). Helper task 553 / 552 results are used unfiltered and before the head model (upstream: after; same output). Component ties (equal volumes) may break differently. No `convex_hull` step: every upstream entry has it at 0. NaN voxels are replaced by the series minimum |
| Limits | CT in HU only (other units are refused). Head to knee, as trained. `api = 6` (needs 3 for this): the series' orientation is read from `row` / `col` / `normal`, so a radspider that only speaks api 2 refuses the plugin. Open weights: "performance may be degraded for some detailed head-and-neck organ-at-risk structures" (upstream). Disk: 410 MB per converted task. RAM: peak 7.7-8.8 GB measured on the test CT below (5.5 GB for the smaller window of 557 open); a wide body CT adds the band of logits (classes × window depth × rows × columns at 1.5 mm, float32, float16 above 3 GB) and the resampled volume, 1-3 GB more, not measured |
| Speed | CPU, 4 cores, 122×101×112 voxels at 3 mm (244×202×224 at 1.5 mm, 8 windows of 192³): 160-215 s per task once converted, 21-26 s per window. First run of a task adds the download (26 s for 762 MB here) and the conversion (7-10 s). 557 with post-processing on a scan without a head: 189 s (task 553 only); 558: 387 s (553 and 552). Not measured: a GPU, a full-body CT (333×333×600 voxels at 1.5 mm would be 54 windows: about 20 min per task on these 4 cores, by the window count) |
| Licence | Code of both repositories: Apache-2.0 (`LICENSE`). Weights, from `cads/LICENSE_MODEL`, verbatim: open: "License: Creative Commons Attribution-ShareAlike 4.0 International (CC BY-SA 4.0)", for "users who need a model-weight license that permits redistribution of derived weights, including commercial use, under share-alike terms"; research: "License: Creative Commons Attribution-NonCommercial-ShareAlike 4.0 International (CC BY-NC-SA 4.0)", "most academic and non-commercial research use"; reference: "License: CADS customized model license", "Users should review and follow the applicable terms for EXACT09, LOLA11, SLIVER07, and EMPIRE10 when using the reference model weights". The `dataset.json` inside each zip agrees (`"licence": "CC BY-SA 4.0"` / `"CC BY-NC-SA 4.0"`). The text of the customized licence is on the release page, which could not be read here, so that variant is left out. Two older files disagree with this and were not updated upstream: the root `LICENSE_MODEL` of the model repository and the Slicer extension's `LICENSE_MODEL` both say "The model weights released in the Releases section of this repository are licensed under the Creative Commons Attribution-NonCommercial-ShareAlike 4.0 International License (CC BY-NC-SA 4.0)" and announce an open version "under CC BY 4.0" (the open variant that exists is CC BY-SA). Share-alike applies to the converted `.pt` files if you redistribute them. `LICENSE_DATA` asks to cite the paper. Not a medical device |
| Verified (as `org.radspider.cads` 1.1.0) | **Run**, outside the viewer, through radspider's SDK host script (`_radspider_host.py`, protocol 3) with the real weights on TotalSegmentator's `example_ct.nii.gz` (abdomen, lung bases to hips, no head, no upper thorax): all nine open models, and research 551. Against the TotalSegmentator project's own `example_seg.nii.gz` (an independent model, 30 slices of that CT; **not** CADS ground truth), open weights: Dice 0.96-0.98 spleen, kidneys, gallbladder, liver, stomach, lower lung lobes; 0.95 inferior vena cava, 0.91 aorta, 0.87 portal vein, 0.79 pancreas, 0.89 adrenals (551); 0.93-0.98 vertebrae T11-L2 (552); 0.94 colon, 0.94 small intestine, 0.90 duodenum (553); 0.97 deep back muscles, 0.90-0.93 iliopsoas (554); 0.90-0.96 ribs 8-12 both sides (555); 0.83 spinal cord (559). Sides and numbering agree (Kidney R on the patient's right, ribs and vertebrae same numbers). 556 gave plausible labels (bowel space, psoas, rectus abdominis, prostate, rectum) with nothing to compare against. Research 551 against open 551: Dice 0.93-0.99, mean 0.978. The same CT handed over as a sagittal series and with slices superior → inferior: voxel-identical labels. Post-processing on / off changes 12 voxels of 551. Weights: every one of the 18 pinned zips was fetched, hash-checked, converted, reloaded with `weights_only=True` and loaded with a strict state dict (9 through the plugin's download code, 9 through `RADSPIDER_CADS_ZIPS`); a wrong zip and a missing zip are refused with a message. Synthetic: orientation against nibabel (6 orientations incl. tilt), resampling against the upstream call, banded window against a plain one with a tiny random network (15 shape / step cases incl. padding), component rules, hole filling, the head-box branches with stand-in models. **Not run**: upstream CADS / `nnunetv2` on the same scan (installing that package was not permitted where this was written), so equality with upstream output is by code reading only; no CADS ground truth; **557 and 558 on a scan with a head** (here: post-processing on returns nothing after 553 / 552, off returns an empty map), so the head models' quality and the brain box on real data are unverified; thoracic, neck and shoulder structures (heart, esophagus, trachea, upper lobes, humerus, scapula, sternum: not in this CT); research tasks 552-559 beyond loading; CUDA and mixed precision; a full-body clinical CT; a tilted or DICOM-decoded series; the viewer GUI |
