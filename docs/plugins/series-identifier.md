# Series identifier

Plugin id: `org.radspider.series-identifier` · folder: [`../../org.radspider.series-identifier`](../../org.radspider.series-identifier)

TL;DR: a tool that looks at the image on screen and says what the series is (CT phase and kernel, MR sequence, PET/NM type,
radiograph, mammogram, ultrasound, angiography run), its plane or projection, region, laterality and contrast, with a short
explanation of each in the user's language. Deterministic rules over DICOM tags and image geometry for every modality; on MR a
second opinion from **dcm-classifier**, a random forest over 28 header features. No pixels are classified. Educational aid, not
a diagnostic device.

| Entry | Does | Input |
|---|---|---|
| tool *identify* | Table *Item · Result · Evidence* (the tag values that decided each row), a *What this means* section, a closed *Model detail* section (MR) and a closed *Tags read* section. A *Refresh* button re-runs it on whatever the viewport shows now | `input = "image"`, one reusable window |

| Item | |
|---|---|
| Model | Rules (data tables in `seriesid_rules.py` / `seriesid_tables.py`) for every modality, plus on MR the `ova_rf_classifier.onnx` of **dcm-classifier** (BRAINSia; Apache-2.0, Michal Brzus and Hans J. Johnson). Pinned commit `5dcb37384572416da806db69c90bbabcec9819c9`, 312 427 bytes, SHA-256 `808fcd58e237ecc3fa657942d325c12ddbbaaf496cc1f849913e99248cba13e0`, checked before loading. Downloaded on the first MR run to `RADSPIDER_SERIES_ID_DIR`, else `~/.cache/radspider/series-identifier`. Offline: `RADSPIDER_SERIES_ID_MODEL=<file>` (still hash-checked). The `dcm-classifier` package is not used: its feature builder is reimplemented without itk/gdcm/pandas |
| Pipeline | Modality (`ctx.series`) → series kind → plane / projection → region and laterality → contrast; each row keeps its evidence. Plane from the slice normal: axial / coronal / sagittal within 10° of an axis, else "oblique, closest to <plane>". CT: localizer, derived MPR/MIP/VRT, contrast phase, kernel family, dual energy. MR: T1, T2, PD, FLAIR, STIR, T2*/SWI, DWI/ADC/FA, perfusion, MRA, 3D, fat suppression, post-contrast. PT/NM: attenuation correction, static / dynamic / gated, SUV vs counts. CR/DX/RF/PX/IO: view from ViewPosition, else PatientOrientation. MG: view and laterality. XA: LAO/RAO and cranial/caudal with degrees. Other modalities: named, "no rules for this modality". On MR the rules run first, then the model; its verdict is *agrees*, *differs from the rules*, *low probability* (below 0.4) or *unreliable* (acquired diffusion without (0018,9087): no probability shown). A kind the model has no class for shows "no model class". Missing EchoTime / RepetitionTime become -12345 and the model still runs, as in the reference; other missing required fields give "model not run: <tag> missing" |
| Explanations | Static texts in the plugin, marked with `rp.tr`, Spanish in `lang/es.toml`. `lang/template.toml` is regenerated with `python tools/series_identifier_template.py` (the plugin translates table ids through an alias, so the stock generator does not see them). No network, no LLM |
| Limits | **Tags**: the 32-tag API maximum is used up, there is no room for another tag. **Rules**: kernel tables are heuristic and Philips and Canon kernels are not mapped; MR TR / TE / TI cut-offs are heuristic; ProtocolName is read only when SeriesDescription is missing and never decides contrast; "with and without contrast" descriptions (W/WO) are treated as no contrast (safe direction, heuristic); CT "POST CONTRAST" without a phase word gives "not determined" (no generic post-contrast CT result); an ADC / eADC word in the description beats a DIFFUSION Image Type unless the image or series b-values are above 0, so a b = 0 image whose description says "ADC" is read as an ADC map, and so is a DIFFUSION image described as "… ADC" whose b-values sit in private tags only; a Contrast/Bolus Agent of NONE / NO / N / NIL / - / 0 / N/A, NINGUNO / NINGUNA / NO APLICA / SIN or a negation is read as no agent; a short TI (≤ 300 ms) is STIR on a spin-echo IR (SE in Scanning Sequence, whatever the agent) and an IR-prepared T1 on a gradient-echo IR (cardiac LGE / PSIR; post-contrast when an agent is recorded); with Scanning Sequence missing, LGE / PSIR words give the IR-prepared T1 and any other short TI reads as STIR; a short-TE gradient echo is T1-weighted only when spoiled (SP in Sequence Variant, or flip < 35° with TR < 800 ms), else "Gradient echo, weighting not determined"; when the tags show no spoiling, a T1 word in the description is trusted and keeps it T1-weighted (the evidence names the description as the deciding field); double inversion recovery (DIR, TI ≈ 3000 ms) reads as T2 FLAIR; only the water image of a Dixon series is marked fat suppressed; the Spanish "C/C" (con contraste) is not recognised as post-contrast (safe direction); an NM description with both ANT and POST names no view, and "<n> H POST" is read as time after injection; the ultrasound colour row measures the pixels, and only for ultrasound (other modalities never read the image; colour only when more than 0.1 % have a chroma above 10), so a greyscale image with large colour overlays reads as colour; the ultrasound region is read from Body Part Examined only, not from the description; an XA primary angle beyond ±90° is reported as LAO/RAO > 90° (a posterior oblique); MG AT / CV views are heuristic (not in CID 4014); PET attenuation correction inferred from Units is heuristic (BQML is not read as corrected: without an AC / NAC word it gives "not stated"). **Model**: dcm-classifier was trained on brain MR; whether it saw enhanced MR is not stated by its authors. It differs from the reference: the gradient is read from (0018,9089), not (0018,9076); private-tag b-values are unread (classic Siemens / GE / Philips DWI), so four of the 28 features are blind there; an empty-but-present tag is seen as absent (so an empty ScanningSequence takes the "Unknown" default, SE = 1, where the reference gives SE = 0); multi-volume aggregation, the perfusion override and the reference's MISSING_IMAGE_TYPE handling (Image Type absent) are not reproduced; *dwig* vs *tracew* depends on how the host counts gradient directions per series (an enhanced multi-frame object counts once). MR kinds without a model class show "no model class". The host runs one Python process per run, so an offline user without the model pays one failed download attempt (fast, no retries) on every Refresh; the download stops above 1 MiB before the hash check and writes its own temporary file, so two runs downloading at once do not collide; the rules answer regardless. **Host**: DA / DT / TM tags are refused, so there is no date or time reasoning; MPR / reformat planes are not accepted as input; US projection is not in the headers (says so); a chest radiograph without ViewPosition is not determined, as no model with a usable licence exists (`ianpan/chest-x-ray-basic` has none, other candidates publish no weights). **Use**: educational use only; it labels acquisitions and never reads findings |
